# Golden image provenance

`hermit-frame.png` is compared byte-for-byte by `src/generation/golden.spec.ts`.
Regenerate it only from the toolchain below; a different OS, Node version,
`playwright-core` release, or Chromium build can change PNG bytes even when the
rendered picture is identical.

- Generated: 2026-11-26 (inline-SVG frame, manifest-driven colors)
- OS: Windows 11 Pro (25H2), build 10.0.26200, 64-bit (win32 x64)
- Node: v24.11.0
- `playwright-core`: 1.65.1 (pinned exactly in `package.json` and `package-lock.json`)
- `sharp`: 0.35.5 (pinned exactly in `package.json` and `package-lock.json`); the
  native-size Chromium PNG is resized to 60px tall with aspect ratio preserved
- Chromium: `chromium-1255` (`chromium.executablePath()` resolves to
  `C:\Users\hermit\AppData\Local\ms-playwright\chromium-1255\chrome-win64\chrome.exe`;
  the path is resolved at runtime, not hardcoded in product code)
- Size: 10385 bytes
- SHA-256: `fb925b740012cd1d1fa55fea996314182a43542e5c3dc2fb8e4c079ae0483fc1`
- Image: PNG, 151×60, produced from `left=Hello&right=World` with all color
  defaults from `assets/templates/hermit-frame/manifest.json`

## Regeneration

From `backend/`, with dependencies installed. Use the gated flag so the exact
service code path produces the bytes. Omit `height`: the endpoint defaults to
60px, so the golden is the resized 60px PNG.

```powershell
cd backend
npm run build
$env:REGENERATE_GOLDEN = '1'
npx jest --runInBand -t "matches the committed hermit-frame"
Remove-Item Env:REGENERATE_GOLDEN
npm test -- --runInBand
```

An explicit `&height=60` produces identical bytes. The last command must pass
with the regenerated bytes.
